## 1. Announcement (image done)

New course this spring: CS 439 Agentic Software Engineering.

AI coding agents can write code quickly. Turning that code into good software still takes engineering. In this course, each student leads their own team of AI coding agents and learns the software engineering principles and practices that make those agents deliver: requirements, design, testing, review, version control, CI/CD, and security.

## 2. Hook: "Anyone can type a prompt. Engineers make agents deliver."

Anyone can type a prompt. Getting software you can trust out of an AI coding agent is a different skill.

It takes clear requirements, sound design, good tests, careful review, and the judgment to know when the work is actually done. That is software engineering, and it matters more with agents, not less.

CS 439 teaches it, hands-on, with your own team of agents.

## 3. The engineering behind better agents

The engineering behind better agents:

Requirements: acceptance criteria
Design: architecture you own
Context: guiding your agents
Testing: tests as guardrails
Review: plans, designs, and evidence
Version control: small, traceable changes
CI/CD: automated quality gates
Security: your software and your agents

These are the practices that CS 439 is built around.

## 4. Practice spotlights

### 4.1 Requirements: "An agent can only build what you can specify."

A vague request gets you a plausible guess. Clear requirements and acceptance criteria get you software you can check. In CS 439, specifying what "done" means comes before any agent writes code.

### 4.2 Design: "You own the architecture. Agents work inside it."

Agents can produce a lot of code, but the architecture is your decision. Clear boundaries, modules, and interfaces keep each agent change local, understandable, and safe to make. That design work stays with the engineer.

### 4.3 Context: "Your agent knows only what you tell it. Tell it well."

Agents don't know your project's conventions, constraints, or goals unless you give them that context. Writing good project instructions and specifications is an engineering skill, and it shows directly in the quality of the output.

### 4.4 Testing: "Tests are the guardrails your agents run into."

A good test suite tells an agent when it is wrong before you have to. Tests are also how you verify work you didn't write line by line. In CS 439, tests are part of how agents are directed, not an afterthought.

### 4.5 Review: "Review the plan before the code, and the evidence before the merge."

With agents, review moves up a level. Check the plan before any code is written, the design before the details, and the evidence (tests, checks, acceptance criteria) before anything is merged. Deciding what needs human review, and what automation can handle, is part of the engineering.

### 4.6 Version control: "Small, traceable changes you can always undo."

Good version control is workflow design: breaking work into small changes, moving them through branches and pull requests, and keeping a history that explains why each change was made. It makes agent work safe to try and easy to undo.

### 4.7 CI/CD: "Let automation reject bad code before a human has to."

Automated builds, checks, and tests act as quality gates on every change, whether a person or an agent wrote it. Setting up those gates is part of leading a team of agents.

### 4.8 Security: "Give your software and your agents only the access they need."

Security covers both the software you build and the agents that build it. Users should reach only their own data, and agents should touch only what their task needs. Thinking through what could go wrong, limiting access, and checking for security issues is part of the engineering.
